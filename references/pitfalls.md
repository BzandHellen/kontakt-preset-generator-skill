# 踩坑清单（通用）

> 通用文档（去个人化）。只写"踩过、并且会再踩"的条目，保留**判据与教训**；
> 具体的库名 / 文件名 / 本机数值已去掉，需要时以"某库 / 某个 patch"泛指。
> 结论文档按主题分组，**结论变了就改这一条，不要在正文复述历史**。

## A. 环境与执行

1. **`DeveloperFeatures = 0` 时脚本静默不执行** —— 不报错、不写报告，最容易白等。
   任何要启动 Kontakt 的事先跑 `env`。
2. **一个 Lua 脚本 = 一次进程**，而且**不能传参、没有 JSON 库**。
   解法：Node 把配置渲染成 Lua 字面量塞进 `jobs\…\job.lua`。
3. **agent 启动的 Kontakt 没有窗口**（`list_windows` 里连隐藏的都没有）→
   "留个实例给人看"对 AI 自己没用；要人眼看得生成可打开的产物，或借用户自己的窗口。
4. **Kontakt 退出时必报 `0xC0000005`**（stderr 刷一屏 `DoVMUnLock … errno = 158`）。
   与成败无关；**判据是报告有没有 `==== end ====`，不是退出码**。
5. **agent 的 shell 是阻塞的**：前台跑会开 Kontakt / 等界面的长命令时，用户消息看不到、弹框也没人点 → 表现就是"永久超时"。这类命令**后台跑 + 合理超时**。
6. **两个 Kontakt 启动挨太近会撞音频设备** → 新进程可能卡住（实测有一次整块超时、报告全无，隔 20 秒单独重跑就正常）。批量链里**每两段之间留 20–25 秒**；工具支持 `--kill-on-timeout` 掐掉卡住的（默认不掐）。
7. **控制台里中文会乱码**（PowerShell 管道编码）→ 要看中文写进 UTF-8 文件再用读取工具看，或让脚本输出标签全用 ASCII。**别拿乱码输出当结论。**
8. **⛔ 不要用 PowerShell 的 `Get-Content | Set-Content` 往返改中文文件**（PS 5.1 按 ANSI 读、按 UTF-8+BOM 写，中文写坏）。一律用编辑工具改。
9. **Lua 不能注入 MIDI** → 技法 / 力度切换**是否真的生效**没法程序化测，只能人眼 / 人耳。
10. **`Kontakt.get_file_info()` 返回 table**，不能当布尔；字段名要 `pairs` 才知道。

## B. Lua 语言本身

11. **空表是真值**：`local k = JOB.keywords or { 默认列表 }` —— 当注入的是 `{}` 时**默认列表被空表顶掉**，
    一个都匹配不上。要写 `if k == nil or #k == 0 then k = {…} end`。
12. **空串也是真值**：`e.snapshot and "套了" or "没套"` —— 当它是 `""` 时**显示成"套了"**（实际没套）。
    要写 `(x ~= nil and x ~= "") and "A" or "B"`。
13. **Lua 里数字键不能写 `{ 1 = … }`**，要写 `{ [1] = … }`（否则 `'}' expected near '='`）。
14. **`Number("") === 0`**（JS 侧同理）→ 会把"未知 / 没读到"打印成 `0.000`。输出前判 `x !== ""`。

## C. KSP 注入（脚本适配器一类）

15. **⛔ `set_instrument_script_source` 收的是「脚本正文」，不是文件路径**：传路径时 Kontakt 把**路径当 KSP 代码编译** →
    stderr 报 `syntax error [<乐器>, script N, line 1]`，**但 `pcall` 照样返回 true**；回读还会返回你写进去的那串文本
    （写路径就返回路径）→ **只看 pcall 和长度会得出"注入成功"的错误结论。**
    - 要写正文：`set_instrument_script_source(idx, slot, "<KSP 正文>")`。
    - 要用文件：`set_instrument_script_linked_filename(idx, slot, "<绝对路径>")`。
    - **判成功的唯一可靠方式**：看 Kontakt 的 **terminal / stderr** 有没有 `syntax error [...]`，
      或者让脚本产生**可回读的副作用**（例：把读数写进 group 声像，再用 `get_group_pan` 读回）。
16. **KSP 语言四条硬规矩**（都在 stderr 里现过身）：
    ① 顶层 `declare` **不能带初值**（要带初值就放进 `on init`）；
    ② `on init` 里**不能 `call` 用户函数**（把循环内联进 `on init`）；
    ③ 用户 `function` 必须定义在**调用它的位置之前**（KSP 自上而下编译）；
    ④ `{ … }` 注释**必须闭合**（漏了会一路吃到文件尾，报 "line N" 的错）。
17. **KSP `$ENGINE_PAR_VOLUME` 是立方刻度**：`unit = 630000 × 10^(dB/60)`（`630000` = 0 dB），**不是** `10^(dB/20)`。
18. **注入后要独立佐证**：拿产物**在全新进程里**打开，确认脚本槽里确实躺着适配器、读数就是目标值（"加载即生效"才算数）。

## D. 存盘与路径

19. **⛔ `save_multi` / `load_multi` 对「含非 ASCII（中文）的路径」静默失败**：
    A/B 对照只换文件名 —— 中文名那份**存盘后连查三次没有、作业退出后磁盘上也没有**，
    但 **`pcall` 返回 true、Kontakt 终端无任何报错**；ASCII 名那份**立刻**写出。
    - **对策**：Lua 侧一律存 / 读**同目录的 ASCII 中转名**，作业跑完由 **Node `renameSync`** 改成最终（可带中文）名。
    - 教训：**Kontakt 的存盘失败是"哑"的**。凡"目标文件没出现"都要**先怀疑路径字符**（非 ASCII / 特殊字符 / 过长），再怀疑逻辑。
    - **别把"没写出来"默认解释成"还没写完"**：实测文件是立刻出现的（立刻 / +3s / +6s 三次查）。
20. **`save_multi` 不会自己建目录**：目录不存在 → 直接 `[FAIL] save_multi -> path doesn't exist` → 后面"重载回读"当然全失败
    （曾因此**把一批已知能存住的库也误判成"全部复位"**）。写盘测试前先 `mkdir -p`。
21. **"存盘失败 + 旧文件还在" = 假 PASS**（这个坑最阴）：`save_multi` 失败时**不报错**（只返回 false），
    如果目标文件**上一次就存在**，后面的"重载回读"会**读到那份旧文件** —— 而旧文件里恰好也是上次写的同一个值 → 判成"能存住"。
    - 正确判法：**先删旧文件** → 存盘 → **要求"成功且文件确实新写出来"** → 才重载回读；存盘失败直接判"存不进去"，**不要重载**。
    - 也**别读"内存里那台乐器"当回读**（那是刚写完的状态，读出来必然一致 → 假 PASS）。
22. **`load_multi` 的返回值不是 instrument 索引**：重载后要回读，必须另取 `get_instrument_indices()`；拿返回值当索引 → 读到空 → 误判"复位"。
23. **一个没被 `pcall` 包住的调用 = 报告全丢 + Kontakt 干挂**：脚本抛错后 Lua 就结束了，`os.exit(0)` 不会执行 → **报告不写、进程不退**，而工具还在等超时。
    模板里凡是会碰文件 / 库的调用**一律 `pcall`**；工具侧看到 `[kontakt.scripting] [error]` 要**提前收工**并打印日志尾巴（**`print()` 走 stderr**）。
24. **`save_multi` 会"挑库"失败**：同一台机器、同一次运行里，个别库**存不进 multi**（`save_multi` 返回 false；任何目录 / 槽数、甚至"只装载→立刻存盘"都失败），
    而其它库全部能存。装载、读 group 名、写 group 音量都正常，**只有"存 multi"这一步不行**。
    - 日志线索：个别库的数据库 preset 标识报 `CXDB3::getPresetIdentifier - Identifier not found`，伴随 `PresetSlotManager::removeSlot` 报错
      → 怀疑 **Kontakt 的浏览器数据库 / 预置槽状态坏了**（两个实例共用同一个 DB 是头号嫌疑）。
    - 处理顺序：**关掉另一个 Kontakt 实例** → 重试 → 还不行就重启 Kontakt / 让它重建数据库。
    - 教训：遇到"存不进"**先别怀疑自己的代码** —— **换一个库做同一件事**（对照）就能分清是库 / Kontakt 的问题还是我们的问题。

## E. 判据与比对（最容易误报）

25. **判「库复位」要比"写之前的基线"**，不能拿"值很小"当判据：各库基线不同，而且都远小于 1。
    做法：写之前先读一遍基线，重载后**回读 == 基线** → 判「库复位」→ 报 WARN 而不是 FAIL；
    verify 读已存盘的文件拿不到基线 → 只提醒不判死，要判就加清单参数（会干净装载读库默认值）。
26. **机器可读块必须各自命名**：早期几个块都叫同一个名字，解析只拿到第一个 → 所有比对"实际"为空。现在分 `SLOTS` / `LIBS` / `MICS` / `BASELINES` / `ADAPTERS`。
27. **`others` 是通配不是麦名** → 它不该进麦克风期望表（否则永远"找不到 group"）；它的命中数写在报告里。
28. **期望值文件名只带 multi 名 → 同名不同清单会互相覆盖**。已加 `src` 列记来源清单，`gen` / `verify` 发现不一致会提醒。
29. **测试采信前先拿已知事实校准**：一组新测法至少要**同时**复现一个已知 PASS 和一个已知 FAIL
    （拿"已知能存住的库"和"已知复位的库"校准，都对上才采信结果）。
30. **浮点要留容差**：`get_group_pan` 会返回 `39.999996` 这种值 → 比较必须留容差（0.01 量级），否则会把"存活"误判成"复位"。
31. **类型错会被 `try` 抓住而不退出**：`set_group_playback_mode` 要传**字符串**（`"dfd"` / `"sampler"`），传数字报
    `stack index 3, expected string, received number`，**不报错退出** → 你会以为"写了没生效"。
32. **别把"受保护（加密）"当成"写不住"**：存在**脚本受保护、但 group 音量写得进去也存得住**的 patch。
    判据只能是实测（`group_persist` / `gen` 的回读比对），不是"它有没有 protected"。
    —— 附带：那些 patch 的 group 名可能全是**技法·力度**名，**根本没有麦克风 group** → 能写不代表有麦可写。
33. **一个没被 `pcall` 包住的失败会伪装成"全部一致"**：重载失败时不要读内存里那台乐器（那是刚写完的状态）→ 会输出假 PASS。

## F. 坏采样与弹框

34. **坏采样弹的模态框会「卡死整个作业」** —— 不是"只失败那一个 patch"。
    0 字节采样 → Kontakt 弹「Sample could not be loaded … Do you want to continue loading?」，
    Lua **停在 `load_instrument` 上等回答**：整块超时、报告一个都不写（**同块里其它 patch 的结果一起丢** —— 机器可读块是跑完才写的）。
    而 agent 起的实例**没有窗口**（那个弹框看不到），人也不会替它点。
    - 对策：**能预知就跳过**（先扫出 0 字节文件清单）→ `load_test` 用 `--skip=<库>` 跳开；`chunk` 调小（10–30）把损失限制在一小块；坏库**重下之后**再测。
    - 另一种表现：坏采样的库 `load_instrument` **直接失败**（不弹框）→ 失败 ≠ 我们的写法有问题，先看失败在哪一槽、再查 0 字节文件。
35. **换一个库做同一件事**是分清"库/Kontakt 的问题"还是"我们的问题"的最快手段。

## G. 数据 / 结构

36. **同一库里的技法可能分在多个平级目录里** → **名字像 ≠ 同一个东西**（两个不同 patch 默认面板状态不同）。进新库先**把顶层文件和目录一起列**出来。
37. **列目录时要文件和目录一起列**：只列目录会**漏掉同级的 `.nki` 文件**（一体化 patch 常直接在顶层），挑错 patch 家族会得到不同的默认面板模式。
38. **zone 可能极多**（单 patch 数万个）→ 遍历 zone 一定要**设上限并说明截断**。
39. **同一库里不同 patch 的 `protected` 标记可能不一样** → 别用 protected 当唯一判据。

## H. 工具 / 工程侧

40. **插件里 `process.execPath` 不是 node** —— 是宿主自己的单文件运行时。拿它当解释器只会得到宿主的 CLI 参数错误。
    要显式找 node（环境变量 → 常见安装路径 → `where node` → `PATH`）。
41. **改了插件代码要 reload**（比重启服务轻）。工具参数改了也要 reload 才生效。
42. **插件里参数名要显式列进 `args` 白名单** —— 漏了就是"工具收到了但没传给脚本"（多个参数都踩过）。
43. **`required` 可能挡了合法用法**：某工具一开始把某个参数设成必填，但另一种模式不需要它 → schema 校验直接拒绝。**按模式放宽**。
44. **用进程 pid 打正则要取最后一个匹配** —— 输出里先有"已经有一个 Kontakt 在跑（pid …）"的提醒，正则抓到的可能是那个，不是刚启动的实例。
45. **`db_query` 类的"完整路径"标签与第一条路径同一行** —— 用 `^\s+[A-Z]:` 这类正则过滤输出会把第一条漏掉（曾因此误判"索引缺文件"）。
    可靠取路径用完整输出，或直接读索引 CSV。
46. **表格的列名必须和数据 key 完全一致**，否则那一列整列空白（踩过两次）。**空列先怀疑 key，不要当成"没数据"。**

## I. 快照

47. **`.nksn` 只读**：能读到名字、读不到可信的值、**绝不能改**（会破坏 NI 的格式与校验）。
48. **snapshot 必须人在 GUI 里调出来**；脚本改完 group 音量再 `save_snapshot` 那份是**无效的**。
49. **套快照会覆盖的不止"麦克风比例"**，还有 UI 的其它状态——**包括"面板模式"**：
    同一批 patch 不套快照时是一种面板，套上某份快照后全变成另一种（推子态、只开少量麦）。
    → **快照与 patch 家族绑定**：跨家族套用会把目标 patch 的界面状态改掉（不是"没生效"，是"改错方向"）；
    **一个库可能要好几份快照**，按家族各存一份，而且**要在"你想要的那种面板状态"下存**。
    判断有没有串就摆 ±快照 的对照槽给人眼看（详见 `snapshots.md`）。

## J. 验证纪律（总纲）

50. **判"干净"要两头都对**：`save_multi` 失败时不报错（D21 的假 PASS）；路径字符会让文件"根本没出现"（D19 的假 FAIL）。
    先删旧文件、要求文件确实出现、只对**新写出来**的文件回读 —— 两头都成立才采信。
51. **一次验证至少同时复现一个已知 PASS 与一个已知 FAIL**（E29）；**判据一律是回读比对**，不用"有没有 protected"猜。
52. **控制台 / 乱码 / 空列 / 空串 / 空表**：这几样都是"看起来有结论、其实是噪音"的高发区（B11–B14、A7）。

## K. VE Pro（通道侧）

53. **state 只能由 Kontakt 自己产出**：自制 / 拼接的 state 会被静默拒绝（`state/set` 返回 success 但内容不变）。
    所以每条 multi 至少要**人工在宿主里 File → Load multi 一次**（⛔ 拖动文件会崩，用面板菜单）。
54. **别用 `channel/add` 建裸通道**：灌了 state 也不发 MIDI，而且没有默认通道条 FX（如 `Vienna Stereo Pan`）。
    → 正解：**克隆一条 GUI 建的普通乐器通道**（接线/FX/state 全继承），再改名 / 再 `state/set`。
55. **⛔ 绝对不要拿「实例总线」当克隆源**（`Master Bus` 之类）：会让宿主 **UI 冻死**
    —— 进程还在、端口仍 Listen，但 `Responding=False`、CPU 空转、API 一律 socket 断；只能强制结束重启。
    动手前先看清对象：**名字里写着"总线/Master"的，不要拿它做有风险的操作**。
    工具侧已加硬闸：源通道必须「标题不像 master bus」+「有乐器」+「`fxCount ≥ 1`（有默认通道条）」。
56. **判"宿主卡死"的判据**（别猜）：`Get-Process <宿主> | Select Responding,CPU` → `Responding=False` +
    CPU 持续空转 + 端口仍 Listen 但 API 报 `Socket closed while reading response`。

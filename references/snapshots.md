# snapshot（`.nksn`）纪律

> 通用文档（去个人化）。这里不出现具体库的快照文件名与路径；那些放在工作区的
> `profiles.json`（`mic_snapshots`）与个人文档里。

受保护脚本的库，**库内设置（麦克风比例 / 键位 / xfade 模式 / 面板开关）只能靠 snapshot 承载**，
所以这一份很重要。

## 1. `.nksn` 是什么：**明文参数容器**，不是加密文件

| 证据 | 值 |
|---|---|
| 熵（抽样） | **6.5–7.1**（加密的**乐器数据**是 ≈ 8） |
| 头部 | 固定几字节 + 4CC 标记（`DSIN` / `hsin` 一类）；**各文件大小不同、无统一压缩魔数** |
| 压缩帧 | 找不到 zstd / gzip / xz / 7z / lz4 任何已知魔数 → **不是压缩包** |
| 可读参数名 | 随库不同，从**几百条到一千多条**不等 |

**能读到的名字**（说明那些块确实在快照里）：`ARTICULATION` / `legato` / `ks_mono_poly` / `_switch` /
`xfade` / `_mic` / `_dyna` / `artic_name`，以及技法名（`Blurred` / `Tremolo` / `Trills` / `Pizzicato` /
`Repetitions` / `Runs` / `Finger` / `Agile` / `Soft` 这类），还有引擎样式的大写名（`ENV_AHDSR_VOLUME` /
`ATTACK` / `filterCutoff` …）。

**读不到 / 不能做的**：

- **值读不出来**：大量 4–6 字符随机 token（有的是明文名的**末字符被替换**版本）是**混淆段**，
  键位、比例这些**具体数值不在明文里**。
- **绝不能改**：手改会破坏 NI 的格式与校验（和 `.nkm` 同一性质）。
- 所以：**没有"口述 → 直接落地"的路**；唯一手段是「人在 GUI 里调一次 → 存快照 → 脚本搬给全库」。

## 2. 只读体检的三种用法（都不需要 Kontakt）

| 用法 | 干什么 |
|---|---|
| 体检 | 一份 `.nksn` 里有没有带着技法 / 键位 / xfade / mic 那些块 → 判断它是不是一份"调全了的库标准状态"。 |
| 对比 | 两份以上 `.nksn` 的名字集合差异 → 看你的标准状态这轮变了什么。 |
| 当参数表查 | 按**名字**或按**值**找（值会按各编码试一遍），报出命中位置和前后最近的明文名。 |

配套的**对齐感知差分**：先在两份里找锚点（间隔 / 长度可调）对齐，再找"哪几个字节变了 + 旁边叫什么"。
⚠️ 为什么要先对齐：头部固定长度字段、以及每一段"每次保存都不同"的疑似 nonce / 校验区，
**不对齐会错位，出现"99% 都不一样"的假象**。
> 反推参数的思路：同一个 patch 只改**一个** UI 开关，各存一份 → 差异那块就是那个参数的存处。

**它不告诉你可信的值，也不改任何东西。**

## 3. ⛔ GUI 按乐器过滤，脚本没有这个限制

- 在 Kontakt 界面里选 snapshot 时，**只列出该乐器目录下的**（`User Content\<库>\<乐器>\`）
  → 用户在 GUI 里**切不到别的 patch 的快照**。
- `Kontakt.load_snapshot(idx, 绝对路径)` **按路径加载，绕开这个过滤** → **能跨 patch / 跨乐器**。

## 4. 实测：跨 patch / 跨乐器到底成不成立

**跨 patch 搬整包状态 —— ✅ 成立。**
做法：同一个 patch 各做两份（原样 / 套快照），再各存一份 `.nksn`，跟**源快照**比名字集合差异：

| 对比源快照 | 只在前者 | 只在后者 | 文件大小 |
|---|---|---|---|
| 同 patch + 快照 | 1 | **0** | ≈ 源快照 |
| 跨 patch + 快照 | 3 | **16** | ≈ 源快照 |
| 跨 patch 原样 | 62 | **165** | **数倍于源快照** |

→ 跨 patch 套上快照后，状态从"差 165 个名字 / 数 MB"收紧到"差 16 个 / 与源快照同量级"。
**结论：脚本确实把该库的 UI 状态整包搬过去了。**

⚠️ 名字集合**证明不了"值"**（同 patch 的"原样"与"套快照"名字集合也几乎一样）→ 具体某个开关是否也变，得人眼看。

**跨乐器搬 —— ✅ 成立（人眼确认）。** 在一件乐器上调好某个整体设置（例：键位整体移调）存快照，
套到**另一件乐器**上，界面里确实反映了改动。

## 5. ⚠️ 家族差异：套快照会连带改掉"面板模式"

套快照覆盖的不止"麦克风比例"，还有 UI 的其它状态——**包括"面板模式"**。
实测：同一批 patch 不套快照时是 **EASY MIX** 面板，套上某份快照后**全变成 MIC MIX**（推子态，而且只开少量麦）。所以：

- **快照与 patch 家族绑定**：跨家族套用会把目标 patch 的界面状态改掉（不是"没生效"，是"改错方向"）。
- **一个库可能要好几份快照**，按家族各存一份，而且**要在"你想要的那种面板状态"下存**。
- 判断有没有串：摆 ±快照 的对照槽给人眼看（`apply_snapshot --visual --pair="<.nki>|<.nksn>" --save=<对照 .nkm>`）。
- ⚠️ 一个库的 patch 可能分在多个平级目录里，**名字像 ≠ 同一个东西**；同一顶层目录还可能有"一体机 patch"与"分技法 patch"两套（面板模式不同）。进新库先**把顶层文件和目录一起列**出来看清楚。

## 6. 维护建议

- **一个库一个 snapshot** 当"该库的标准状态"，放在 `User Content\<库>\<乐器>\`。
- 改完用只读体检**对比旧的那份**，确认"想改的变了、不想改的没变"。
- 给全库套用走 `apply_snapshot`：**输入 multi 永不被覆盖**（默认输出 `<名> (snap).nkm`）；`slots="0,2"` 可只套部分槽；
  逐槽不同快照用 `pair="<.nki>|<.nksn>"`；两库也能混在一个 multi 里。
- 这类库的比例**不落在 group 音量上** → 数值上读不出来，只能人眼确认（摆对照 → 用户点槽 → AI 截屏）。

## 7. 脚本适配器（MIC-ADAPTER）与三条路的关系

库内设置落地一共三条路，**先认库属于哪条**：

| 路 | 用在什么库上 | 与快照的关系 |
|---|---|---|
| ① 清单里直接写 group 音量 | 未加密、写得住 group 音量的库 | 不需要快照。 |
| ② **脚本适配器 `MIC-ADAPTER`** | group 音量**会被库复位**、但**有空脚本槽**的库 | 不需要快照：往空脚本槽注入一小段 KSP，`on init` 写一次、`on persistence_changed` / `on ui_update` 每次兜一遍；**随 `.nkm` 存盘、加载即生效**。 |
| ③ 快照 `.nksn` | 脚本槽**全受保护**的库；以及**注入不持久 / 被库清槽**的库 | 库自带 UI 状态的整包搬运，是这类库的唯一通路。 |

**判据（谁走哪条）：**

| 观测 | 结论 |
|---|---|
| 写了 group 音量，存盘重载后**回读一致** | 走 ①（实测为准，不看 protected）。 |
| 回读 == 写之前的基线（被复位），且**有空脚本槽**、注入后重载槽内容还在、值对 | 走 ②。 |
| 脚本槽**全部 protected**（连空名槽也是） | 只能走 ③。 |
| 注入"成功"但**加载后槽内容被清/变短、marker 没动**、也不随 `.nkm` 存住 | 该库大概载入时清槽 → 只能走 ③。 |
| 复位只是**部分**（例：min 复位、max 存活） | 以能存住的那部分为准，其余走 ③。 |

⚠️ 走 ② 的前提是 KSP 注入真的跑起来——判"跑了"**只看可回读的副作用**，
不能只看注入调用的返回值或源码长度（见 `pitfalls.md` 的「KSP 注入」组）。
⚠️ 走 ③ 时，**数值验不了**：快照里的值在混淆段，只能靠对照槽 + 人眼看。
